# Десктоп приложение администрирования игры «Морской бой»

Объектно-ориентированное программирование, Технологии программирования,
Математико-механический факультет, СПбГУ.

## Описание

Десктопное приложение для администрирования партий классического «Морского боя»
между двумя игроками. Приложение выступает арбитром одной партии: расставляет и
проверяет корабли, принимает и проверяет ходы, определяет результат выстрела и
победителя, а затем сохраняет партию в базе данных и обновляет рейтинги.

Возможности:

- создание и хранение игроков;
- создание партии между двумя игроками;
- автоматическая расстановка кораблей по правилам (корабли не пересекаются и не касаются, в том числе по диагонали);
- проверка расстановки кораблей;
- проверка ходов: статус партии, очерёдность, повторный выстрел по одной клетке;
- запись истории ходов (промах, попадание, потопление, победа);
- определение победителя;
- пересчёт рейтинга после завершения партии (победитель получает от +25 до +33, проигравший теряет столько же, но не больше своего рейтинга; начальный рейтинг 1000);
- статистика игроков: сыграно партий, побед, винрейт, рейтинг;
- история всех партий со статусом, победителем и числом ходов;
- прерывание партии: она остаётся в истории со статусом «Прервана» и в статистику не входит;
- сохранение всех данных между запусками.

Правила хода: после промаха ход переходит сопернику, после попадания или
потопления стреляет тот же игрок.

## Технологии

- **Язык:** Kotlin 1.9.22
- **Сборка:** Gradle Wrapper
- **GUI:** Compose for Desktop, Material 3
- **Хранение:** SQLite через `sqlite-jdbc`
- **Тестирование:** JUnit 5

## Сборка и запуск

```bash
./gradlew build # сборка и тесты
./gradlew test  # только тесты
./gradlew run   # запуск приложения
```

## Хранение данных

База данных находится в файле `~/.battleship/battleship.db` и создаётся при первом запуске.

| Таблица   | Содержимое                                                        |
|-----------|-------------------------------------------------------------------|
| `players` | игроки (уникальное имя)                                           |
| `ratings` | текущий рейтинг каждого игрока                                    |
| `games`   | партии: игроки, победитель, статус, время создания                |
| `moves`   | ходы партий: номер, игрок, клетка, результат выстрела             |

Расстановка кораблей в базе не хранится, поэтому продолжить партию после закрытия
приложения нельзя. Незавершённые партии при следующем запуске помечаются как
«Прервана».

## Архитектура

Проект разделён на слои, зависимости направлены внутрь, к `domain`:

- **`domain`** — модель (`Game`, `Board`, `Ship`, `Coordinate`, `Move` и т. д.), сервисы
  (валидация расстановки и ходов, рейтинг, статистика) и интерфейсы репозиториев.
  Не знает ни о базе данных, ни о GUI.
- **`application`** — `GameSession`: координатор одной партии; `RandomShipPlacer`:
  генератор расстановки.
- **`infrastructure`** — реализации репозиториев: SQLite для приложения,
  in-memory для тестов.
- **`presentation`** — Compose-интерфейс и `GuiController`, связывающий его с остальными слоями.

Диаграмма классов: [`diagram.puml`](diagram.puml).

