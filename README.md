# Десктопное приложение администрирования игры «Морской бой»

Объектно-ориентированное программирование, Технологии программирования,
Математико-механический факультет, СПбГУ.

## Описание

Десктопное приложение для администрирования партий классического «Морского боя».

Приложение не является игрой для самостоятельного прохождения. Администратор заносит
в систему расстановки кораблей и уже выполненные игроками ходы, а приложение проверяет
корректность партии, поддерживает состояние игры, хранит историю, рассчитывает рейтинг
Эло и локальную статистику игроков.

Приложение предоставляет:

- регистрацию и хранение игроков;
- отображение текущего рейтинга Эло;
- создание партии между двумя реальными игроками;
- ручную расстановку кораблей и её полную проверку;
- дополнительную автоматическую генерацию корректной расстановки;
- проверку допустимости ходов;
- занесение и сохранение полной истории ходов;
- определение результата и победителя партии;
- пересчёт рейтинга Эло после завершения партии;
- отображение статистики по игрокам;
- просмотр полной истории партий с расстановками, ходами и рейтингами;
- работу через графический и консольный интерфейсы;
- локальное долговременное хранение данных в SQLite.

Графический интерфейс реализован с использованием Compose Desktop.

## Хранение данных

Основное приложение использует SQLite независимо от выбранного интерфейса.

База создаётся автоматически при первом запуске и находится по адресу:

```text
~/.battleship/battleship.db
```

В базе хранятся:

- игроки;
- текущие рейтинги Эло;
- партии и их статус;
- победители;
- все ходы;
- расстановки кораблей обоих игроков;
- состояние клеток обеих игровых досок;
- изменения рейтинга по итогам партии.

In-memory репозитории используются только в тестах, чтобы unit-, integration- и system-тесты
не зависели от пользовательской базы данных.

## Сборка

Для сборки проекта необходимо выполнить:

```bash
./gradlew clean build
```

## Запуск GUI

GUI запускается стандартной задачей Compose Desktop:

```bash
./gradlew run
```

Интерфейс содержит три основных раздела:

1. **Игроки** — регистрация игроков и просмотр их статистики.
2. **Новая партия** — выбор двух игроков и создание партии.
3. **История партий** — просмотр сохранённых партий и полных подробностей.

## Запуск консоли

Консольная версия запускается отдельной задачей:

```bash
./gradlew console
```

Консоль и GUI используют одну и ту же SQLite-базу и видят одинаковых игроков, рейтинги
и историю партий.

## Работа с расстановкой кораблей

Основной способ расстановки — ручной ввод.

Формат:

```text
A1-A4; C1-C3; E1-E3; G1-G2; I1-I2; G4-G5; A7; C7; E7; G7
```

Для кораблей длиной больше одной клетки указываются начальная и конечная координаты.
Для катера достаточно одной координаты.

Проверяется:

- наличие ровно 10 кораблей;
- состав флота: 1 линкор, 2 крейсера, 3 эсминца, 4 катера;
- корректность координат;
- положение корабля строго горизонтально или вертикально;
- отсутствие пересечений;
- отсутствие соприкосновений, включая диагональные.

В GUI доступна отдельная кнопка **«Авторасстановка»**. Она является вспомогательным
вариантом и не заменяет ручной ввод.

## Работа с партией

После создания партии администратор последовательно заносит расстановки двух игроков.
После начала игры можно записывать ходы в формате `A1` ... `J10`.

Правила очередности:

- `MISS` передаёт ход сопернику;
- `HIT` оставляет ход тому же игроку;
- `SUNK` оставляет ход тому же игроку;
- `WIN` завершает партию.

При победе автоматически рассчитываются изменения рейтинга Эло и сохраняются текущие
значения рейтингов.

## История партии

Для каждой сохранённой партии можно посмотреть подробный отчёт, содержащий:

- игроков и статус партии;
- все ходы с номерами, игроками, координатами и результатами;
- полную расстановку кораблей первого игрока;
- полную расстановку кораблей второго игрока;
- состояние игровых досок;
- победителя;
- рейтинг каждого игрока до партии;
- рейтинг каждого игрока после партии;
- изменение рейтинга.

Один и тот же `GameHistoryFormatter` используется для консольного и графического интерфейса,
поэтому содержимое отчёта одинаково.

## Архитектурные решения

### Разделение бизнес-логики и хранения

`GameSessionImpl`, валидаторы и модели не содержат кода работы с SQLite. Они обращаются
к интерфейсам `PlayerRepository`, `GameRepository` и `EloRatingRepository` из Domain-слоя.

Это позволяет использовать в-memory реализации в тестах без изменения игровой логики.

### SQLite для всех пользовательских сценариев

И GUI, и консоль используют SQLite-реализации репозиториев. Это обеспечивает единое
долговременное состояние приложения независимо от выбранного интерфейса.

### Полное сохранение состояния партии

В SQLite сохраняется не только строка партии и история ходов, но и обе расстановки,
состояние клеток игровых досок и изменения рейтинга. Поэтому полная история восстанавливается
после повторного запуска приложения.

### Незавершённые партии

Если администратор закрывает текущую сессию до победы, партия сохраняется со статусом
`ABANDONED`, чтобы в истории не оставалась зависшая активная игра.

### Отсутствие игровой логики бота

Приложение предназначено для администрирования реальной партии между двумя игроками.
Бот не участвует в Domain- и Application-логике.

## Тестирование

Тесты разделены по назначению, при этом основные проверки работают с in-memory репозиториями,
а отдельные тесты проверяют SQLite-слой во временных файлах.

Проверяются:

- value objects и модели Domain-слоя;
- координаты, корабли и игровая доска;
- валидатор расстановки;
- валидатор ходов;
- рейтинг Эло;
- случайная расстановка как вспомогательный механизм;
- полный жизненный цикл партии;
- очередность ходов;
- прерывание незаконченных партий;
- статистика игроков;
- GUI-контроллер;
- сохранение и восстановление игроков в SQLite;
- сохранение и восстановление рейтингов;
- сохранение и восстановление партий и ходов;
- сохранение и восстановление расстановок, состояний досок и Elo changes;
- внешние ключи и обновление партий без дублирования данных.
